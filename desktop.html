The desktop

A screen is wall space. These are two things to hang on it — a museum wall and a bookshelf — both generated locally, from data, with nothing phoning home.

A desktop background is looked at more often than anything anyone hangs in a house, and it is usually a stock photograph. These two small tools treat it as what it is: the most-seen surface you own. One hangs paintings on it, with the little plaques. The other builds a bookshelf out of the books you have actually read, spine by spine. Both run entirely on your machine.

Interactive

The bookshelf

Drop in a Goodreads export, give it your screen size, and download the wallpaper. The page is the whole application — it parses the CSV, draws the shelf and writes the PNG in the browser, and works with the network cable out.

The gallery

A command-line generator that composes a triptych of paintings — or a single work, centred — over a near-black wall, each with a museum plaque: title, artist, date, medium. Five collections are configured, and a collection is just a folder with a manifest.

Download code and manifests

The gallery

The generator reads a collection manifest, picks works, lays them out as fractions of whatever canvas size it is given — detected from the screen on Windows, stated with --size anywhere else — and never scales an image above its native resolution. A painting filter keeps sculpture and furniture off the wall; a seed makes any wall reproducible.

The download contains code and metadata, not images. Each collection ships a fetch.py that retrieves the pictures from the museum’s own public site onto your machine, politely and resumably. That split is deliberate: the museums publish the images for looking at, and a metadata manifest plus a fetcher respects that arrangement; a zip of their files would not. The works in the staged collections are public-domain paintings; the photography of them belongs to the institutions.

The bookshelf

Goodreads exports a CSV of everything you have shelved. The app reads it and builds a case of book spines sized to your screen: a spine’s width follows its page count, and the shelf holds whichever slice of the library you ask for — read, reading, or the aspirational pile.

What is real: titles, authors, page counts and years, straight from the export. What is chosen: the cloth colours, bands, labels and lettering are drawn deterministically from each title, so the same book always gets the same spine — but the spine is a design, not a photograph of your edition. The page states the same split, because sonification and visualisation projects usually blur it.

Install and removal

Neither tool installs anything. The gallery is a folder; the bookshelf is one HTML file. Setting the wallpaper on Windows is the one act that touches state outside the folder, so it is made reversible: before the first change, the path of the current wallpaper is saved to a single JSON file next to the script, and --undo restores it and deletes the file. No registry keys are written, nothing runs at startup, and removal is deleting the folder.

The code

Python 3.10+, with Pillow as the gallery’s only dependency; the bookshelf is dependency-free HTML and JavaScript. Both downloads are on the code page.
